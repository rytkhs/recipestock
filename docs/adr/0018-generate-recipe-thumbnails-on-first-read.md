# 一覧用サムネイルを初回取得時に生成してR2へ保存する

一覧はカバーの元画像を配信していた。URL取り込みの画像は縮小されずにR2へ保存されるため、小さな表示枠でも大きな画像の通信とデコードが必要になる。一覧の`coverImageUrl`を専用APIへ切り替え、詳細・拡大表示には元画像を使う。

## 変換と保存

Cloudflare Images binding (`IMAGES`) にR2の元画像を渡し、幅・高さ640px以内、`fit: scale-down`、WebP、品質80、`anim: false`で生成する。この仕様を`v1`として固定する。グリッドとリストは同じ画像を使い、表示枠での切り抜きは既存のCSSが担う。任意のサイズ・品質・外部URL指定は受け付けない。

元画像`recipes/{userId}/{recipeId}/{imageFile}`に対して、URLは`/api/images/thumbnail/v1/recipes/{userId}/{recipeId}/{imageFile}`、保存先は`recipes/{userId}/{recipeId}/_thumbnails/{imageFile}/v1.webp`とする。拡張子を含むファイル名を用いるため、異なる元画像が同じ保存先に衝突しない。

RecipeContentには元画像キーだけを保存する。DBマイグレーションや既存画像の一括変換は不要。新規保存・取り込み完了にも変換を追加しない。品質やサイズの変更は別バージョンのURLと保存キーにする。

## 配信と認証

認証とキーの所有者検証後、R2 HEADで元画像の存在を確認し、派生画像があれば配信する。元画像がなければ派生画像は取得しない。派生画像の条件付きGETはR2の`onlyIf`へリクエストヘッダーを渡し、条件不一致でbodyのないobjectが返った場合は304にする。ADR 0012のセッションキャッシュを利用し、画像の所有者判定に新たなDB照会は追加しない。元画像APIと同様、画像ルート自体ではプランや現在のRecipeContent参照を照会しない。一覧APIはロック中の画像URLを返さない。

派生画像がなければ元画像を取得し、変換、R2保存、元画像の存在再確認を行って応答する。保存完了を待ち、通常は手元の変換結果を返す。変換結果を公開CDNキャッシュへ保存せず、ブラウザへは既存と同じ`private, max-age=604800`を指定する。`If-None-Match`は派生画像のETagに対して評価し、304を返す。

入力は4セグメントの元画像キーに限定する。エンコードされたスラッシュ、バックスラッシュ、制御文字、tmpや派生画像のキーを拒否する。既存の`/object/*`からの`_thumbnails`へのアクセスも拒否する。

## 競合と削除

Worker間の重複変換は許容する。R2の条件付きPUTで未保存の場合だけ書き込み、競合時は先に保存された画像とそのETagを取得して応答する。分散ロックは導入しない。

元画像削除時は画像単位の派生prefix以下を全バージョン削除する。tmp削除では派生画像の検索を行わない。Recipe削除では既存のRecipe単位prefix削除に派生画像も含まれる。カバーから外しても工程などで元画像が参照される場合は保持する。

生成後に元画像が消えていれば派生画像を削除して404にする。ただし複数オブジェクトの削除と生成はアトミックではないため、競合や削除失敗で孤立ファイルが残る可能性はある。既存と同じbest-effortの削除であり、次の配信時には元画像の存在確認により孤立ファイルを配信しない。ブラウザにキャッシュ済みの画像は最大7日残り得る。

## エラーと観測

認証失敗は401、他ユーザーのキーは403、不正入力は400、未知のバージョンや元画像なしは404とする。Cloudflare Imagesの9412（画像ではない）、9413（100MP超過）、9520（非対応形式）と、自前の入力サイズ超過は恒久的な入力エラーとして422 (`thumbnail_source_unsupported`) を返し、通常のブラウザ再読込による再変換を抑えるため`private, max-age=3600`を設定する。元画像が同じキーで置き換わった場合に長期間失敗を残さないよう、R2には失敗状態を保存しない。原因不明を含むその他の変換失敗と保存失敗は503 (`thumbnail_unavailable`) とし、`no-store`を設定する。元画像へのフォールバックや同一表示中の自動再試行は行わない。UIは画像エラーをプレースホルダーで表し、タイトルとリンクは引き続き利用できる。

初回生成時は`recipe_thumbnail_served`ログにmiss、所要時間、出力容量、変換時間、元画像容量、保存競合を記録する。高頻度になるキャッシュヒットごとのログは出さない。失敗は`recipe_thumbnail_failed`に恒久・一時の分類と、取得できた場合はCloudflare Imagesのエラーコードを記録する。

## 導入・検証

Cloudflare Imagesの利用が追加される。画像のホスティングはR2を継続するため、必要なのはImagesの変換機能とWorker bindingである。変換とR2保存・読み書きに利用量が発生する。Workersの有料プランとは別に、公開前に対象アカウントのImagesの利用可否・上限を確認する。ローカル開発では低忠実度の変換実装に限定されないようImages bindingを`remote: true`にし、代表的な実画像でCloudflare Imagesとの結合を確認する。

自動テストはR2とImagesの代替を用いて、初回生成、再利用、R2条件付きGETによる304、認証、入力検証、保存競合、削除競合、恒久・一時エラー、派生削除、UIの失敗表示を確認する。Cloudflare Imagesの実際のデコードと変換はこの代替では保証されない。

公開前の実機検証では、代表的な写真・縦長スクリーンショット20枚を使い、元画像・初回生成・生成済みの3条件で画像転送量、最初の4枚の表示完了時間、画質を比較する。特に初回変換を含めて表示が改善することを確認する。自動テストの成功はこの性能確認を代替しない。

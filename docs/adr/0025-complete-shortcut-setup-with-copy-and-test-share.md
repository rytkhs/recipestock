# Shortcut連携のセットアップを発行・コピー・試し共有で完結させる

ShortcutはPWAのCookieを持たず、ユーザーごとに連携トークン入りのShortcutを配ることもできない（Shortcutの署名はmacOSでしかできない）。連携トークンをShortcutへ渡す経路は、追加時のインポート質問しかない。Shortcutの初回実行でペアリングしてトークンをiCloud Driveのファイルへ保存する案は、更新できない場所に分岐と保存先を置くためADR 0008に反する。インポート質問へ貼り付けてもらう方式は変えない。

変えるのはその前後である。従来の設定カードは、端末名の入力、発行、「トークンをコピー」、「Shortcutを追加」を別々の操作として並べていた。コピーしないまま追加へ進めると、インポート質問で貼るものがない。空欄や別の文字列のまま追加しても、初めて本当に共有するまで失敗に気づけない。

## 発行・コピー・移動を1回のタップにする

端末名は入力させず、UAから「iPhone」「iPad」を既定の名前にする。一覧は端末名、追加日、末尾4文字で見分ける。

「ショートカットを追加」のタップで、発行、クリップボードへの書き込み、iCloudリンクへの移動を順に行う。Safariのクリップボード書き込みはユーザー操作の中でしか許されないため、発行を`await`する前に`navigator.clipboard.write`を呼び、発行APIの応答を`ClipboardItem`へPromiseとして渡す。移動はコピーが成功してからにする。コピーできなかったときだけ、トークンの表示とコピーボタンと追加リンクを出す。この表示がないと設定を完了できないためである。

設定を開いた時点で発行しておき、タップで同期的にコピーする案は採らない。開いただけで使われない連携トークンが溜まる。

## 設定の中で試しに共有してもらう

設定カードは`navigator.share`で`<APP_ORIGIN>/shortcut/test`を共有させる。Shortcut向けendpointは、認証とcredential単位のrate limitを通過したあと、取り出したURLのoriginが`APP_ORIGIN`と一致し、pathが`/shortcut/test`であれば、Import Jobを作らずに`setup_verified`を返す。保存上限にもAI利用回数にも数えない。

ADR 0008のnoticeはreasonを足してもShortcutの改修を要しないため、Shortcutは変えない。貼り付けの失敗、共有シートの中でのShortcutの位置、初回実行時の送信許可を、ユーザーがレシピを保存しようとしている場面ではなく設定の中で済ませる。

## 初めて認証に成功した時刻だけを記録する

`shortcut_credentials.first_used_at`を追加し、認証に成功したときに値が空であれば書き込む。条件は`UPDATE`の`WHERE first_used_at IS NULL`に置き、認証の`SELECT`と同じ単一SQL（ADR 0001）で行う。2回目以降は該当行がなく書き込みが起きない。ADR 0006の「認証のたびに利用日時を永続化しない」はこの形で維持し、「credential一覧は発行日時とtoken suffixを端末識別情報として公開する」に`firstUsedAt`を加える。

設定カードは、サーバーの一覧から状態を決める。iOSはShortcutsアプリへ切り替えている間にPWAを読み込み直すことがあるため、画面内の状態に頼らない。最も新しい連携トークンの`firstUsedAt`が空なら接続待ちとして試し共有へ誘導し、値があれば連携済みとする。使われていない連携トークンは自動で失効させず、一覧に未接続として出す。試し共有を飛ばしたユーザーのShortcutを後から壊さないためである。

発行数に対する`first_used_at`の割合と、発行から初回利用までの時間は、DBから取れる。空欄のまま追加されたShortcutは連携トークンに辿り着かないため、`unauthorized`のログに`authFailure`（`missing_token`または`unknown_token`）を付けて分ける。

## 再連携の案内に`openUrl`を使わない

Shortcutの「URLを開く」はhttpsのURLをSafariで開く。Safariはstandaloneではないため、設定カードは「ホーム画面へ追加してください」しか表示せず、再連携の導線にならない。仮にPWAが開いたとしても、失うのは設定画面までの1タップである。`unauthorized`と`malformed_request`は`openUrl`を持たず、`body`でRecipe Stockの設定から追加し直すよう伝える。試し共有で失敗したユーザーは、すでに設定画面にいる。

上限到達時の課金画面への`openUrl`と、Shortcutの手順5そのものを残すかどうかは、この決定に含めない。

## 採らなかった案

- **使われていない連携トークンを一定時間で失効させる**：一覧は整理されるが、試し共有を飛ばして後日初めて共有したユーザーが`unauthorized`になる。
- **端末名を変更するAPI**：追加日と末尾4文字で見分けられる。
- **アプリ側の計測イベント**：発行から初回利用までの割合はDBとログで取れる。

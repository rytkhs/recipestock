# 戻る・閉じるは履歴を戻り、戻る先がなければ親の画面を開く

画面の戻るボタンは、ADR 0021で一覧へ戻るときの条件の引き継ぎを決めたとき、どれも「覚えている絞り込み条件を付けて一覧を開く」ようにした。当時の戻るボタンは詳細・取り込み・設定・新規作成にあり、どれも一覧から入る画面だったので、行き先は一覧で合っていた。方式は、並び順をメモリに覚えて一覧へ移るときに補う既存の仕組みを、絞り込み条件へ広げたものだった。

その後、一つの画面に一覧以外の入口が増えた。タグの管理は詳細のシートと設定から開け、プランは一覧のロック中の案内・詳細・取り込みの上限エラーから開け、編集は一覧のカードからも開ける。戻るボタンは固定の画面をpushで開くので、設定から開いたタグの管理の戻るで一覧が開くなど、来た画面へ戻れない。端末やブラウザの戻るとも行き先がずれ、アプリの戻るで積んだ一覧から端末の戻るを押すと、離れたはずのタグの管理が再び出る。

## 来た画面へ履歴を戻る

画面左上の戻る・閉じるは、履歴を1つ戻って来た画面へ帰す。端末やブラウザの戻ると同じ行き先になり、一覧のスクロール位置・絞り込み・並び順も離れたときのまま戻る。読み上げ名は、行き先が経路で変わるので「戻る」「閉じる」とだけ言う。

戻る先があるかは、TanStack Routerの履歴が各エントリーに持つ番号（`__TSR_index`）で判断する（`history.canGoBack()`）。ページを読み込んだときの最初のエントリーは0になり、アプリの外から来た場合も同じである。URLを直接開いたとき、Push通知（`WindowClient.navigate`）、iOS Shortcut、Stripeの決済・契約管理やOAuthから戻ったときは、どれも戻る先がないと判断できる。アプリの中で戻る先として不適切なのはログイン画面だけなので、ログイン後の移動は履歴を置き換える。

## 戻る先がなければ親の画面に置き換える

戻る先がないときは親の画面を開き、今のエントリーと置き換える。pushすると、端末の戻るで同じ画面が再び出る。

| 画面 | 親 |
|---|---|
| 詳細 | 一覧 |
| 編集 | 詳細 |
| 新規作成・取り込み | 一覧 |
| 設定 | 一覧 |
| 設定の各ページ・プラン | 設定 |
| タグの管理 | 設定 |

タグの管理は設定の目次に項目があるのでそこを置き場とし、一覧のチップ列の「編集」と詳細のシートの「タグを管理」は近道として扱う。

## 完了した操作は、操作した画面を履歴に残さない

保存・送信・削除のあとは結果に合った画面へ移り、戻ったときに操作した画面が再び出ないようにする。

- **編集の保存**：来た画面へ戻す。一覧から編集したなら一覧へ、詳細から編集したなら詳細へ帰り、「保存しました」を短く知らせる。ADR 0021が履歴を戻す方式を採らなかった理由の一つは、保存すると詳細へpushで移るので戻ると編集画面に着くことだった。保存を「戻る」にしたので、この問題は起きない。
- **新規作成の保存**：作ったレシピの詳細を開き、新規作成のエントリーと置き換える。詳細の戻るで来た画面に帰る。
- **取り込みの送信**：これまでどおり条件を外した一覧を開き、取り込みのエントリーと置き換える。テキストの取り込みからURLの取り込みへの切り替えも置き換える。
- **詳細での削除**：詳細の戻ると同じく来た画面へ戻す。詳細の入口は一覧なので、一覧に帰る。
- **決済からの戻り**：Stripeを経ると履歴は続かないので、戻るは設定を開く。Proになった知らせには、一覧への入口を添える。取り込みの上限エラーから来た場合でも元の画面へは帰さない。帰すには決済の戻り先URLに経路を載せることになるが、起きる回数に見合わない。

## 一覧の絞り込み条件はURLだけに持つ

履歴を戻ると、一覧は離れたときのURLのまま開く。戻る先がないのは読み込み直した直後だけで、そのとき覚えている条件は空である。ADR 0021の条件をメモリに覚える仕組みと、一覧から開いた詳細に付けていた履歴の印（`openedFromRecipeList`）はなくす。消したタグの絞り込みが戻った一覧のURLに残っても、一覧はタグ一覧を読んでからそのidを外す。

並び順のメモリは残す。ヘッダーのリンクのように並び順を指定しない移り方で引き継ぐのに使っている。

## 採らなかった案

- **画面ごとに戻り先を固定する**：今の作りである。入口が増えるたびに、戻り先を直すことを思い出す必要がある。今回の問題も、「戻る画面は一覧から入る」という前提が書かれないまま入口が増えて起きた。
- **経路を履歴のstateに載せて画面ごとに分ける**：リンクごとに印を付け、戻り先の組み合わせを画面が持つことになる。入口を足すたびに両方を直す必要があり、戻り先を固定する案と同じ問題が残る。
- **戻る先がないときも親をpushで開く**：端末の戻るで、閉じた画面が再び出る。

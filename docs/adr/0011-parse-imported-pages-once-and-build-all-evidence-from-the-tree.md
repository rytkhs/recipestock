# 取り込むページのHTMLは1回だけパースし、AIに渡す証拠をすべて同じ木から作る

汎用の取り込みでは、取得したHTMLをparse5で1回だけパースし、AIに渡すmarkdown・構造化証拠（JSON-LD・microdata・RDFa）・タイトル・画像候補をその木から作る。テキストはどれも`import/html.ts`の1つの描画関数で作り、JSON-LDの文字列に入ったHTMLも同じ関数でテキストにする。HTMLRewriterは文字参照を戻さず木も作らないため、HTMLRewriterで読んでいた頃は、文字参照のデコード・区切り・非表示の除外を経路ごとに作り直すことになり、経路どうしで結果が食い違っていた。

CSSは見えないので、表示はUAスタイルシートで推す。テキスト中の文字にはさまれた改行は残し（CSSのpre-wrapで改行を出すページがある）、要素の端の空白や改行は畳む。サイトごとのadapter（`deterministic/`）は、決まった要素をHTMLRewriterのセレクタで拾う使い方のままにし、文字参照はparse5と同じ`entities`で戻す。

## 採らなかった案

- **HTMLRewriterとhtml2md4llmのまま、漏れを1つずつ直す**：html2md4llmは正規表現でHTMLを切り分ける実装で、文字参照を一部しか戻さず、入れ子が深いページでは処理時間が指数的に増える。漏れを塞ぐたびに、タグの許可リストとマーカーによる補正が増えていた。
- **HTMLRewriterのイベントから自前で木を組む**：暗黙の終了タグなど、パーサが行う木の構築を作り直すことになる。
- **htmlparser2**：parse5より速くメモリも少ないが、木の作り方がブラウザと同じではない。parse5でも1件の処理時間は十分小さい。

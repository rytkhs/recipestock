# ショートカット連携の設定をインストールの前提から外す

ADR 0006は、Shortcut連携のセットアップ（連携キーの発行とShortcutの追加）をstandalone表示のPWAにある設定画面だけから提供すると決めた。この前提はADR 0004のShare Handoffから引き継いだものである。Share Handoffでは、Shortcutが`webapp:`でPWAを起動し、PWAが共有URLを受け取っていたので、PWAのインストールは連携が動くための条件だった。

ADR 0006でShortcutはImport Jobを直接作成するようになり、取り込みはサーバーだけで完結している。PWAの起動も、PWAがインストールされていることも、取り込みの成否に関わらない。インストールで得られるのは、iOSでWeb Pushを受け取れることだけである。それでもセットアップをstandaloneに限っていたため、Safariで使っている人は、ホーム画面への追加・追加したアイコンからの開き直し・PWA側での再ログインを済ませるまで、アプリで最も価値の大きい機能に届かなかった。

連携キーの発行とShortcutの追加は、PWAをインストールしていなくても提供する。連携している端末の一覧と解除はアカウント全体の情報なので、どの環境からでも扱えるようにし、なくした端末の連携を別の端末から止められるようにする。

インストールは、それが実際に効く場所で勧める。完了通知の段で、通知に対応しておらず、かつstandaloneでない環境には「ホーム画面に追加して、そこから開くと通知を受け取れる」と伝える。この条件に当たるのは、実際にはほぼiOSとiPadOSのブラウザである。主要なデスクトップとAndroidのブラウザはWeb Pushに対応しているので、この案内は出ない。User-Agentで端末を判定せず、機能の有無とdisplay modeだけで分ける。

## 採らなかった案

- **standaloneに限ったまま、インストールの手順を詳しく案内する**：インストールの動機にはなるが、実際には不要な手順を連携の前に置くことになる。インストールを済ませずに連携をやめる人が出ることの損失が、インストールが増えることの利益より大きい。
- **環境ごとに出し分ける**（Apple製品以外にはショートカットの案内を出さない）：Androidでは、インストールしたPWAがmanifestの`share_target`でOSの共有を受け取れるので、ショートカットの案内は要らない。ただし端末の判定と、環境ごとの案内の作り分けが要る。これは連携のオンボーディングを設計するときに合わせて決める。

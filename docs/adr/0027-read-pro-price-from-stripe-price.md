# Proの値段はStripeのPriceから読む

プランのページで「Proにする」の前に値段を出す。値段を見ずに押させるのは不親切で、押す前に値段・支払いの間隔・解約できることが分かるのは、特定商取引法の最終確認画面の考え方にも沿う。

値段の出どころはStripeのPrice（`STRIPE_PRO_PRICE_ID`）にする。Checkoutで実際に請求するのはこのPriceなので、画面の値段と請求額が必ず一致する。コードや環境変数に金額を書くと、Stripeで値段を変えたときに画面だけが古い値段のまま残る。お金の表示は間違えたときの害が大きいので、出どころを一つにする。

`GET /api/billing/pro-price`がPriceを読み、`{ amount, currency: "jpy", interval: "month" }`を返す。画面は「月額 ¥480（税込）」と出す。税込で見せるのはこのプロダクトの決めごとであり、Stripeの税の設定からは読まない。

## Priceが想定と違えば止める

画面の文言は「円・1か月ごとの定期払い」を前提にしている。設定したPriceがそうでなければ（ドル、年払い、3か月ごと、一回払いなど）、APIは設定の誤りとしてエラーにしてログに残す。別の値段を「月額」と書いて見せるより、出さないほうがよい。

## Workerのisolateで覚える

Priceは、作ったあとに金額と支払いの間隔を変えられない。値段を変えるときは新しいPriceを作り、`STRIPE_PRO_PRICE_ID`を差し替える。そのため同じIDについては一度読めば足り、isolateが生きている間はメモリに覚えておく。ページを開くたびにStripeへ問い合わせることはない。

## 値段を読めなくても申し込みは止めない

値段は課金の状態とは別の問い合わせにする。Stripeに届かず値段を読めなくても、プランのページのほかの部分は出る。そのときは値段の行だけを出さず、「Proにする」は押せるままにする。Stripeの決済画面にも値段が出るためである。

## 採らなかった案

- **金額をコードの定数か環境変数に書く**：Stripeを一度も呼ばずに済むが、値段の出どころが二つになる。
- **値段を出さない**：Stripeの決済画面で初めて値段が分かる。押す前に分かるべきである。
- **`/api/billing/status`に値段を含める**：値段が読めないと、プランと契約の状態まで出せなくなる。

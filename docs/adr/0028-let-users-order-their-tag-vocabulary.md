# タグの並びを利用者が決める

タグの語彙は、付いているRecipeの件数が多い順に並べていた（ADR 0022）。一覧のチップ列は横スクロールで、モバイルでは先頭の3〜4個しか見えない。絞り込みでよく使うタグでも、付いているRecipeが少なければ後ろに回る。件数は付け外しのたびに変わるので並びも動き、付け外しのシートは開いている間に語彙を取り直すため、候補の順が押した直後に入れ替わる。並びを利用者が決められるようにする。

## 件数では並べ替えず、利用者が決めた並びで揃える

`tags.position`を持ち、語彙を出すところはこの並びで揃える。一覧のチップ列、タグの管理画面、付け外しのシートの候補のどれも同じ順になる。

- 件数では並べ替えない。付いているRecipeの数と、絞り込みに使う頻度は一致しない。
- 新しく作ったタグは語彙の末尾に入る。シートで作っても、定番候補から選んでも同じである。
- 付け外しのシートは、開いてから語彙が最初に届いた時点で語彙もそのRecipeのタグも空なら、閉じるまで定番候補を定番の順に並べ、選んで作ったタグも位置を動かさない。届く前に自分でタグを作った回は、並びがずれないよう定番候補を出さない。次に開いたときは語彙の順になる。
- 名前の変更・統合・削除は他のタグの位置を変えない。統合先は自分の位置を保つ。
- 詳細画面に出るタグは、これまでどおりそのRecipeに付けた順のままにする。語彙の並びとは別のもので、付け足した順に読める方が分かりやすい。
- `position`には一意制約も索引も置かない。並びは`position, created_at, id`で決まるので、同時に作って値が重なっても、消して隙間ができても困らない。
- 導入時の位置は、それまでの並び（件数降順→`created_at`→`id`）をマイグレーションで固定する。入れ替えた時点では棚の見え方が変わらない。

## 並びは全体を送って置き換える

`PUT /api/tags/order`にタグのidを並べた配列を送る。ADR 0022の組の置き換えと同じく、同じ内容を送り直しても結果は変わらない。位置の更新はADR 0001に従い単一SQLで行う。

- 送られなかった自分のタグは、今の相対順のまま後ろに回す。自分のものでないidと消えたidは無視する。別の端末でタグを作った・消した直後でも、衝突として返さずに収める。
- 画面は押した時点で並びを当ててから送る。同じ利用者の要求は順に送り、後から押した並びが最後に届くようにする。

## 並べ替えるのはタグの管理画面だけにする

行の「⋮」に「先頭に移動」「上に移動」「下に移動」を置き、材料・手順の並べ替えと同じ操作にそろえる。一覧のチップ列は横スクロールで、押すと絞り込みが切り替わるので、そこでは並べ替えない。

## 採らなかった案

- **ドラッグ＆ドロップ**：チップ列やシートでは横スクロールとぶつかる。管理画面に置くにも、タッチとキーボードの作り込みと新しい依存が要る。まず行メニューで出し、語彙が長くて並べ替えきれないとなってから考える。
- **ピン留めして、残りは件数順**：「ピン」と「並び」の2つを覚えることになり、ピン留めしていないタグの並びは結局動く。
- **最後に絞り込みに使った順**：並びが勝手に動く問題が大きくなる。
- **並べ替えるまでは件数順、一度並べたら手動**：2通りの並び方が同時にあることになり、画面で説明できない。
- **`position`を小数や文字列で持つ**：語彙は多くても数十件なので、並び全体を送って整数で振り直す方が単純である。

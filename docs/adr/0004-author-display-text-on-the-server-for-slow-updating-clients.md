# 更新の遅いクライアントの表示文言はサーバーが決める

iCloudリンクで配布したShortcutはインストールした時点で固定され、強制アップデートもテレメトリもない。Service Workerも`skipWaiting()`を使わないため、PWAを開いたままの利用者のもとでは、古いworkerが長くpushを処理し続ける。こうしたクライアントには、URLの抽出や表示文言のような将来変わる判断を置かない。表示する`notice`はサーバーが確定し、クライアントはそれをそのまま出す。

## Shortcutへは想定内の結果をすべて200で返す

Shortcutの「URLの内容を取得」は、非2xxを受けると実行を止めてAppleのエラーダイアログを出す。そうなると、こちらの文言を一切表示できない。そこでShortcut向けendpointはREST APIではなく、更新できないクライアント向けのRPCとして扱う。認証失敗を含め、想定内の結果はすべて200で返し、`outcome`・`reason`・`notice`を付ける。HTTPステータスで見ていた異常は、`reason`別のログで監視する。

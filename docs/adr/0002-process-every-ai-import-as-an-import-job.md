# AI取り込みはすべてImport Jobとして非同期に処理する

URL、貼り付けたテキスト、iOS Shortcutのどの入口からの取り込みもImport Jobを作り、Cloudflare Queueで非同期に処理する。成功したら確認を挟まずにRecipeを保存する。active Jobの再利用、保存上限、AI利用上限の判定は、入口によらず1つの投稿処理で行う。入力の種類で変わるのは、同じImport Jobとみなす条件だけである。

## 上限は投稿時に確かめ、消費はキュー処理中に行う

投稿時は当月のAI利用回数を照合するだけにし、消費はキュー処理中の原子的なUPSERTで行う。そのため、上限の1回手前で同時に投稿すると、1件が投稿時の判定をすり抜ける。すり抜けた1件はキュー処理中の消費で`ai_usage_limit_exceeded`として失敗するので、上限そのものは破られない。

## 取り消しても利用回数は戻さない

取り消したImport JobはRecipeを作らないが、始まっていたAIの処理は止めず、消費したAI利用回数も戻さない。失敗したJobと同じく、返す処理を持たない。

## 採らなかった案

- **AIの結果を手入力フォームへ流し込み、利用者が保存する同期API**：AIを待つ間にPWAがバックグラウンドへ回ると、結果が失われて利用回数だけが減る。上限の判定と、保存上限を含む原子的な保存を、別の経路で作り直すことにもなる。
- **投稿時に消費し、失敗したら返す予約制**：返す処理と、返す前に落ちたときの漏れへの対策が必要になり、境界の1件のためには見合わない。
